# Desktop integration

fff can be the machine's file manager, not only a launcher from the shell:
directories opened by other programs (`xdg-open`, a launcher) open in fff, a
browser's "Show in folder" opens fff with the file highlighted, and Firefox and other applications that use the
desktop portal pick files with it. `fff setup` installs each part:

```sh
fff setup --desktop        # open directories in fff
fff setup --file-chooser   # pick files with fff in Firefox and other apps
```

`--browser` is another name for `--file-chooser`.

Both run fff in a new terminal window using `[open] fff_terminal` from the
configuration (`st -c fff-picker -e` by default; see
[openers](CONFIGURATION.md#openers)), which a window manager can
[float](#floating-windows). Set it before running setup, and run setup again
after changing it or after moving the fff binary: the files it writes name
both.

## Floating windows

fff started from another program is a short-lived picker, best shown as a
floating window over the current layout rather than a new tile. The default
`fff_terminal`, `st -c fff-picker -e`, gives every such window the X11 class
`fff-picker`. fff does not float the window itself: that is up to your window
manager, which needs a rule for that class. In i3 (`~/.config/i3/config`),
for example:

```
for_window [class="fff-picker"] floating enable, resize set 1500 1000, move position center
```

With another window manager, write the equivalent rule in its own
configuration (sway: `for_window [app_id="fff-picker"] floating enable`;
dwm: a `rules[]` entry with class `fff-picker` and `isfloating` set), or pick
another class in `fff_terminal` and match that. Other terminals set the class
differently: `alacritty --class fff-picker -e`, `kitty --class fff-picker`,
`xterm -class fff-picker -e`, and on Wayland `foot --app-id fff-picker`. Use
the same class for your own launchers, e.g. `st -c fff-picker -e
findnotes-fff`, and they float alike.

Setup reports every file it writes or leaves unchanged on stderr. Files fff
generated (they say `Generated by fff setup`, or `Generated by fff --setup`
before 0.9) are replaced when run again;
any other file at the same path is never overwritten, and setup stops and asks
you to move it aside. Existing configuration files are edited one key at a
time, keeping everything else.

## Opening directories

`fff setup --desktop`:

1. Writes `$XDG_DATA_HOME/fff/open-folder` (`~/.local/share/...` by default),
   a launcher script running `FFF_TERMINAL fff window FOLDER` with the
   terminal's own output discarded (st, for one, logs escape sequences it does
   not support, and that log would otherwise land in the shell that ran
   `xdg-open`).
2. Writes `$XDG_DATA_HOME/applications/fff.desktop`, an application for
   `inode/directory` whose command is that script. A script keeps the entry's
   `Exec` line free of quoting: `xdg-open` outside a desktop environment
   splits it at spaces and does not understand quotes.
3. Refreshes the desktop database with `update-desktop-database` when it is
   installed.
4. Writes `$XDG_DATA_HOME/dbus-1/services/org.freedesktop.FileManager1.service`,
   so that the session bus starts fff to answer "Show in folder" (see
   [below](#show-in-folder)), and asks the bus to reload its configuration.
5. Makes it the default for directories with
   `xdg-mime default fff.desktop inode/directory`, checks that it took effect,
   and names the previous default and how to restore it. Without `xdg-mime`,
   it prints that command instead.

`fff window` starts at the path it is given; given a file, fff starts in its
folder with the file highlighted. Started from a menu without a path, fff
browses from the directory the launcher starts in (usually your home
directory).

The entry runs the terminal itself instead of setting `Terminal=true`: with
`Terminal=true` each launcher chooses the terminal from its own list (GIO, used
by Firefox and GTK applications, does not know st) without the window class,
so the window would neither float nor be the same from program to program.

Check it with:

```sh
xdg-mime query default inode/directory   # fff.desktop
xdg-open ~/Downloads                      # fff in a floating terminal
```

`fff window` is fff with a window of its own and no shell to change into,
so the keys that would leave into a directory act like a graphical file
manager instead. Normal-mode Enter on a folder (or on a folder in the marked
list, or the Select button) enters it and fff stays. Enter on a file opens it
with its [opener](OPERATIONS.md#opening-files) and closes the window, as a
double click would (a GUI opener keeps running; a terminal opener takes over
the window until it ends); `l` opens it in the background and keeps fff open.
`!` replaces fff with your `$SHELL` (`/bin/sh` when unset) in the folder you
are browsing, so the window becomes a terminal there; leaving the shell closes
it. `q` closes the window. Nothing is printed. The F1 guide describes Enter
and `!` this way in such a window.

Launchers and portal wrappers written before 0.16.4 call `fff --browse
--window` and `fff explorer --multiple` (and the like), which now only say
what replaced them; run `fff setup --desktop` and `fff setup --file-chooser`
again to update them. `fff window --resume` continues the last `fff roam` or
`fff window` session.

## Show in folder

Firefox's "Show in folder" (and other programs' "Open containing folder")
asks a file manager over D-Bus, through `org.freedesktop.FileManager1`. The
service file setup writes lets the session bus start
`fff dbus-file-manager LAUNCHER` on the first such call; it runs the
`open-folder` launcher on each item, so fff opens in a new window in the
item's folder with the item highlighted. Folders asked for with
`ShowFolders` open themselves (`ShowItemProperties` is answered like
`ShowItems`); several items in one folder open one window,
highlighting the first. The service exits after ten minutes without calls,
and the bus starts it again when needed.

When another file manager is already running and owns the name (Nautilus,
Dolphin), it answers instead, and fff is not asked. A service file in your
own `$XDG_DATA_HOME` takes precedence over those installed system-wide, so
fff is started when no file manager is running. Remove the service file to
stop answering; without it, programs fall back to opening the containing
directory, which opens in fff without the highlight.

The bus starts the service with its own environment, which must include
`DISPLAY` (or `WAYLAND_DISPLAY`) for the terminal to open a window. Desktop
environments arrange this; with a bare window manager started from
`startx` and a systemd user bus, add
`dbus-update-activation-environment --systemd DISPLAY XAUTHORITY` (or
`WAYLAND_DISPLAY`) to its startup. Check it with:

```sh
gdbus call --session --dest org.freedesktop.FileManager1 \
  --object-path /org/freedesktop/FileManager1 \
  --method org.freedesktop.FileManager1.ShowItems "['file://$HOME/.bashrc']" ""
```

## Picking files in Firefox

Applications that use the xdg-desktop-portal FileChooser ask the portal for a
file dialog; [xdg-desktop-portal-termfilechooser](https://github.com/hunkyburrito/xdg-desktop-portal-termfilechooser)
answers by running a wrapper script that opens a terminal file manager. Install
it first (on Arch, the AUR package
`xdg-desktop-portal-termfilechooser-hunkyburrito-git`), then:

```sh
fff setup --file-chooser
systemctl --user restart xdg-desktop-portal
```

and in Firefox, open `about:config` and set
`widget.use-xdg-desktop-portal.file-picker` to `1`, then restart Firefox: it
reads the setting only when it starts. File dialogs then open fff.

If they still do not, check the portal on its own; this opens fff as Firefox
would:

```sh
gdbus call --session --dest org.freedesktop.portal.Desktop \
  --object-path /org/freedesktop/portal/desktop \
  --method org.freedesktop.portal.FileChooser.OpenFile "" "Test" "{}"
```

No fff window means the portal is the problem (`journalctl --user -u
xdg-desktop-portal` says which implementation it chose for the FileChooser);
a window means Firefox is not using the portal.

Setup changes three files under `$XDG_CONFIG_HOME` (`~/.config`):

| File | Change |
| --- | --- |
| `xdg-desktop-portal-termfilechooser/fff-wrapper.sh` | The wrapper script, written whole. |
| `xdg-desktop-portal-termfilechooser/config` | `cmd` names the wrapper, `create_help_file=0`, and `default_dir=$HOME` when unset. |
| `xdg-desktop-portal/portals.conf` | `org.freedesktop.impl.portal.FileChooser=termfilechooser` under `[preferred]`. |

When a desktop-specific file exists, it is edited instead, as each portal
reads that one first: `xdg-desktop-portal-termfilechooser/$XDG_CURRENT_DESKTOP`
and `xdg-desktop-portal/DESKTOP-portals.conf` (the desktop name lowercased).
Setup warns when it cannot find the portal's `termfilechooser.portal` file.
Replacing a previous `cmd` switches the dialogs from that wrapper to fff; set
it back to undo.

### Using the dialog

Each dialog runs [`fff explorer`](#fff-explorer), a mode made for answering
file dialogs. In short:

| Dialog | How to choose | The application receives |
| --- | --- | --- |
| Open a file (attach, upload) | Enter on a file | That file. |
| Open several files | Space to mark (Tab or Shift+Space while typing), then Enter on a file (or Ctrl+w) | The marks and that file. |
| Choose a folder | Go into it and press `!` (or Ctrl+s) | That folder. |
| Save (a download, a PDF from the viewer) | Go to the folder and press Ctrl+s (or `!` after Escape: a save dialog starts typing the name) | The suggested name in that folder. |
| Save under another name | Go to the folder (Alt+l and Alt+h while typing, or Escape to browse), type the name, Enter (or Ctrl+s) | That name in that folder. |

`q` (or Ctrl+c while typing) cancels, as the footer says beside `F1 keys`. The
empty query line says how to choose, and when saving, the query box's title
says the name the file will get. Saving over an existing file always asks
first.

### The wrapper

The generated script records the fff binary and the terminal. `TERMCMD`, the
variable termfilechooser's own wrappers use, overrides the terminal for one
run or for good, e.g. from the portal configuration (keep a window class there
for the window to float):

```ini
[filechooser]
cmd=/home/you/.config/xdg-desktop-portal-termfilechooser/fff-wrapper.sh
env=TERMCMD=foot --app-id fff-picker
```

The terminal's own output is discarded unless the portal's log level is
debug. The terminal must stay open until fff exits (most do; a terminal that hands
the command to an existing server and returns at once cancels every dialog).
The script needs bash. With the portal's log level at debug
(`--loglevel=DEBUG`), it traces its commands in the
portal's log.

## fff explorer

```
fff explorer open [PATH]
fff explorer open-multiple [PATH]
fff explorer folder [--multiple] [PATH]
fff explorer save [PATH]
```

Answers one file dialog and prints the answer: each chosen path, absolute,
followed by a newline. The file chooser installed by `fff setup --file-chooser`
runs it for every dialog, but it works anywhere a script needs a file, a folder
or a place to save. The general options (`--depth`, `--hidden`,
`--no-exclusions`, `--palette`, `--no-icons`, `--config`,
`--no-config`) apply as usual and may follow the subcommand. The
subcommands are named as the [Keys screen](CONFIGURATION.md#where-keys-apply)
names their programs (`explorer-open`, ...); one folder and several share
`explorer-folder`, since their keys do not differ.

### Kinds of dialog

| Command | Dialog | Answer |
| --- | --- | --- |
| `open` | Open one file | One file. |
| `open-multiple` | Open several files | One or more files. |
| `folder` | Choose a folder | One folder. |
| `folder --multiple` | Choose folders | One or more folders. |
| `save` | Save a file | One file path, which may not exist yet. |

### Where it starts

| PATH | Starts in | Highlighted |
| --- | --- | --- |
| none | The current directory | — |
| A folder | That folder | — |
| An existing file | Its folder | That file |
| A file that does not exist (usual when saving) | Its folder, if that exists; else the current directory | — |

A relative PATH is taken from the current directory. The session is never
saved for `fff --resume`, so dialogs do not disturb your own sessions. Browsing is otherwise the usual:
navigation, filtering, depth, hidden entries, tabs and bookmarks all work.

When saving, the suggested name is PATH's file name; without a PATH, or when
PATH is a folder, it is `untitled`.

### Keys

The keys keep their meaning from a normal session (see the
[README](../README.md#browsing-and-returning-paths)): Enter acts on the
highlighted entry, `!` on the folder you are in, Ctrl+w on the marks (in
`open-multiple` and `folder --multiple` only). What differs:

| Key | In `fff explorer` |
| --- | --- |
| Enter on a folder | Enters it, in Normal and Insert mode alike (a normal session leaves into it from Normal mode). |
| Enter on a file | Chooses it, in Normal and Insert mode alike. With one answer (open one file) it is that file whatever is marked; in `open-multiple`, the marks and that file. When saving, offers to [replace](#saving) it. |
| Enter while typing (Insert mode), when saving | Saves under the typed name, as in any name field. |
| Enter with nothing listed (an empty folder), when saving | Saves under the typed or suggested name. |
| Enter in the marked list | Chooses that mark (when saving, offers to replace it). |
| `!` (Normal mode) | Takes the folder being browsed: the answer to a folder dialog, or where to save. |
| Ctrl+s | Like `!`, and also while typing: saves here, or chooses this folder. Nothing in open dialogs. |
| `q` (Normal mode) | Cancels, as everywhere: nothing is chosen. |
| Ctrl+c | Cancels. |
| Ctrl+w | Chooses the marks, in `open-multiple` and `folder --multiple`. Other dialogs have one answer, which Ctrl+w does nothing for but say so. |
| Ctrl+number | Enter on that row: chooses a file, enters a folder, offers to replace a file when saving, also while typing a name to save under. |
| Double click | Enter on that row, as Ctrl+number (a normal session acts like `l`). |
| `l`, Alt+l, Alt+number | Enter a folder, as in a normal session. In open and save dialogs, on a file they open nothing (those dialogs choose files): the status line says to press Enter on it or Ctrl+number on its row, to choose it or, when saving, to replace it. In folder dialogs a file opens in the background, as in a normal session. |
| `gX` | Cancels without running the program (`gx` runs it and comes back, as usual). |

File operations (move, copy, delete, rename, new file or folder, extract)
remain available, so a dialog can also make the folder to save into.

### Hints

The query line, while empty, says how to choose instead of `type to filter
names…`. Typing (Insert mode) changes it, since `!` is then text:

| Dialog | Normal mode | Insert mode |
| --- | --- | --- |
| Open one file | Press Enter on a file to choose it. | the same |
| Open several | Press Enter on a file to choose it. Press Space to mark several, then Ctrl+w to choose them. | the same |
| Folder | Press ! or Ctrl+s to choose the folder you are in. | Press Ctrl+s to choose the folder you are in. |
| Save | Press ! or Ctrl+s to save NAME here. Press i to type a custom name. Press Enter on a file to replace it. | Type a custom name, then press Enter or Ctrl+s to save it here. Press Esc to browse folders. |

How to leave without choosing is in the footer, to the right of `F1 keys` and
in the same style: `q quit`, or `Ctrl+c quit` while typing.

When saving, the query box's title is `Save as NAME`: the typed name, or the
suggested one while the query is empty. It updates as you type.

### Saving

The name is the query, trimmed of surrounding spaces, or the suggested name
when the query is empty. In a save dialog the query does not filter: every
entry stays listed, and the names it matches have their matching letters
highlighted, so files with similar names stand out as you type. A name cannot contain `/` or a line
break, nor be `.` or `..`; the status line says so and nothing is saved.

`!`, Ctrl+s, and Enter while typing save under that name in the folder being
browsed:

- **Nothing of that name there:** the dialog ends with that path.
- **A folder of that name:** refused; the status line suggests Enter to go
  into it.
- **A file or link of that name:** the **Replace** window asks first:
  - **Enter** replaces it;
  - **k** keeps both, saving as the first free `NAME (1).EXT`,
    `NAME (2).EXT`, ... (`paper (1).pdf`; a name without an extension, or
    starting with a dot, is numbered at its end);
  - **Escape** goes back to choosing, to type another name or folder.

Enter on an existing file (in the results or the marked list) opens the same
window for that file.

### The answer

The paths a key returned become the answer as follows:

- **Open:** folders are dropped, so a folder returned by `!` or Ctrl+w counts
  as nothing. In `open`, only the last remaining path is kept: the
  file Enter was pressed on, or the last mark.
- **Folder:** files are dropped. Without `--multiple`, only the last folder is
  kept.
- **Save:** the path [saving](#saving) settled on.

Paths containing a newline are left out of open and folder answers, since the
answer has one path per line.

Nothing is written for a cancelled dialog or an empty answer.

### Exit status

| Code | Meaning |
| --- | --- |
| 0 | An answer was printed. |
| 1 | Startup, configuration or I/O error. |
| 2 | Invalid usage, e.g. no kind of dialog. |
| 130 | Cancelled, or nothing chosen fits the dialog; nothing printed. |

### Examples

```sh
fff explorer open ~/Downloads                # choose one file, starting in Downloads
fff explorer open-multiple | xargs -d '\n' ls -l
fff explorer folder --multiple               # choose folders
fff explorer save ~/Downloads/paper.pdf      # where to save paper.pdf
```
